## 2. Prompt & Schema Specification (`src/prompts.py`, `src/schema.py`, `src/parse.py`)

### 2.1 Complete Rubric Evaluation (CRE) Prompt (`src/prompts.py`)
Combine Pathak et al.'s CRE prompt (`BITS-Pilani-GRC/Rubric-Grader`) with Koutcheme et al.'s 3-step template (`KoutchemeCharles/cip25-aiep`):
- **System Prompt**:
  - Instructs the model to act as an expert C++ university instructor performing **Complete Rubric Evaluation (CRE)** across the entire question-specific rubric in a single pass.
  - Explicitly mandates:
    1. *"Evaluate the code strictly on logical correctness and algorithmic intent."*
    2. *"Ignore all syntax errors, compilation errors, missing headers, missing semicolons, variable naming choices, and spelling mistakes. Treat any syntax error as valid syntax and infer the student's logical flow and intention."*
    3. *"Any valid algorithmic approach (loops, arrays, arithmetic division/modulo, conditionals, helper functions) that satisfies a criterion's logical goal earns full marks for that criterion."*
- **User Prompt**:
  - Problem description
  - Question-Specific Rubric (criterion ID, description of logical goal, `max_marks`)
  - Optionally 1–2 structurally distinct reference solutions (controlled by ablation flag `INCLUDE_REFERENCE`)
  - Student C++ submission with 1-indexed line numbers (`1: ...`, `2: ...`).
- **Assistant Output (3-Step Format)**:
  1. `Let's think step-by-step.` followed by one reasoning paragraph per rubric criterion in exact rubric order: stating the requirement, citing exact student code line numbers (`line X`), explicitly pardoning any syntax/naming/spelling quirks on those lines, and stating the criterion verdict and score.
  2. A single JSON block conforming to `schema.py` (`criteria`: list of `{id, marks_awarded, max_marks, evidence_lines, justification}`, plus `needs_human_review: bool`).
  3. `Feedback:` A 3-sentence constructive sandwich feedback block: (a) praise all satisfied logical criteria, (b) explain at most the first two failed logical criteria in rubric order, (c) end with an encouraging sentence.

## 3. Two-Stage Distillation & Alignment Pipeline (`nb1b_teacher.ipynb` → `nb2_train.ipynb` → `nb2b_nca.ipynb`)

### 3.1 Notebook 1B: Ground-Truth Anchored Teacher Generation (`notebooks/nb1b_teacher.ipynb`)
- Load the Teacher Model $\pi_\tau$: `Qwen/Qwen2.5-Coder-14B-Instruct` (or `Qwen/Qwen3-14B` with `enable_thinking=False`) in 4-bit NF4 on Kaggle $2\times\text{T4}$.
- For each training/validation record $(d^i, s^i, r^i)$ with known ground-truth criterion marks $g_{\text{true}}^i$ and diff/mutation provenance:
  - Prompt $\pi_\tau$ with $(d^i, s^i, r^i)$ **plus** a ground-truth instructor note specifying the exact marks $g_{\text{true}}^i$ and which lines contain the logical bug or syntax/naming transform.
  - Generate $C_O = y_{\text{win}}^i = (t_\tau^i, g_\tau^i, f_\tau^i)$ via greedy decoding (`do_sample=False`).
- **Verification Gate**: Automatically validate every generated $C_O$:
  1. `parse_and_validate_output(C_O)` succeeds with `is_valid == True`.
  2. Every criterion mark in $g_\tau^i$ equals $g_{\text{true}}^i$.
  3. Every line number in `evidence_lines` exists in $s^i$.
  4. Reasoning text $t_\tau^i$ contains no syntax-penalty phrases.
- Strip the ground-truth instructor note from the prompt and save the clean `(Student Prompt, Teacher Output C_O)` pairs to `cpp-grader-data-v2/train_sft_v2.jsonl` (and JSON-only targets to `train_sft_v2_direct.jsonl`).

### 3.2 Notebook 2: Stage 1 Student SFT (`notebooks/nb2_train.ipynb`)
- Student Model $\pi_\theta$: `Qwen/Qwen3-4B` (with `enable_thinking=False` locked) or `Qwen/Qwen2.5-Coder-3B-Instruct`.
- 4-bit NF4 QLoRA, `fp16` compute on T4, gradient checkpointing, completion-only loss masking (loss computed only on assistant output tokens $C_O$).
- Verify under the Qwen tokenizer that `max_seq_length` exceeds the p99 of `prompt + C_O` and drop any record whose JSON target is truncated.
- Select the best checkpoint at each epoch using generated mark agreement (QWK + Exact Match + Leniency $l_n$) on a fixed 100-example subset of `val_unseen`.

### 3.3 Notebook 2B: Stage 2 Student vs. Teacher NCA Alignment (`notebooks/nb2b_nca.ipynb`)
- Following Koutcheme et al. (SIGCSE 2026) and Chen et al. (NeurIPS 2024):
  1. Load the trained Stage 1 SFT Student ($\pi_{\text{sft}}$, Arm A2) and run greedy decoding on the training/validation pool to produce the Student's outputs $C = y_{\text{lose}}^i = \pi_{\text{sft}}(x^i)$.
  2. Filter for examples where the Student's output $C$ disagrees with the Teacher's ground-truth marks ($g_{\text{sft}}^i \neq g_\tau^i$, prioritizing false penalties on valid alternative approaches or syntax-broken code).
  3. Form preference triples $(x^i, y_{\text{win}}^i = C_O, y_{\text{lose}}^i = C)$.
  4. Train Arm A3 ($\pi_{\text{nca}}$) using TRL's `DPOTrainer` with `DPOConfig(loss_type="nca_pair", beta=0.1, learning_rate=5e-6, num_train_epochs=1)` on 2,000–5,000 pairs.
